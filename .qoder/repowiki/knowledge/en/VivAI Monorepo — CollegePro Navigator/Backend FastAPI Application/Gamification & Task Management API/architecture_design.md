Two FastAPI routers expose the functionality: `backend/api/gamification.py` mounts a single `/api/gamification` endpoint returning a user's gamification payload via `gamification_service.get_gamification`, while `backend/api/tasks.py` provides full CRUD plus status updates and bulk reorder under `/api/projects/{project_id}/tasks`. The service layer in `backend/services/gamification_service.py` is stateless and interacts directly with Supabase through `core.database.get_supabase()`, reading/writing `profiles`, `achievements`, `viva_sessions`, and `presentation_sessions` tables. All database calls are wrapped in try/except blocks so missing migration columns cause silent no-ops, keeping existing flows intact. Authentication and authorization are enforced at the route layer via `Depends(get_current_user)` and `require_project_owner`; side effects (activity logging, XP awarding) are delegated to `services.activity_service.log_activity` rather than being inline.

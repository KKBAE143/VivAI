- Gemini function declarations are defined as `types.Tool(function_declarations=[types.FunctionDeclaration(...)])` lists returned by a dedicated `_tools()` / `_team_tools()` helper, keeping schema and description co-located with the prompt's usage rules.
- SDK compatibility shims wrap every call that may vary across `google-genai` versions in try/except falling back to an alternative signature (e.g. `send_realtime_input(audio=...)` vs `media=...`, `response.data` property vs scanning `server_content.model_turn.parts[]`).
- Language handling is centralized: `_language_directive` and `_transcription_language_hints` produce both the spoken-language instruction injected into the system prompt and the STT `language_hints` list, ensuring the same locale mapping drives output and transcription consistently.
- Per-session state is accumulated in a small persistence class (`LivePersistence`, `TeamLivePersistence`) that buffers events and writes them in a single batch via `flush_events()`, with finalize running off the event loop via `asyncio.to_thread` so the report LLM call does not block the WebSocket.
- Tool-call responses include a minimal `{"status": "ok"}` plus an extra field (`question_id`, `id`, or `instruction`) keyed on the function name, so the caller can enrich the next model turn without changing the response shape contract.

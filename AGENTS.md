# VivAI

AI-powered companion app for college students — projects, teams, AI Mock Viva, AI Presentation Mock, college predictor, sentiment/weakness heatmaps.

## Stack

- **Frontend** (`src/`): TanStack Start (React 19, Vite 8, Nitro) + TanStack Router (file-based routes) + TanStack Query + Tailwind v4 + Radix UI + react-hook-form / zod.
- **Backend** (`backend/`): Python FastAPI + Supabase (Postgres + auth + storage) + Google Gemini (`google-genai`).
- **Deployment target:** Cloudflare Pages / Workers (Nitro `cloudflare-module` preset).

## Common commands

First-time setup on a fresh Windows machine (installs Bun + Python if missing, creates the backend venv, installs ALL frontend/backend packages, and writes `backend\.env` + `.env.local` with placeholder values):

```powershell
.\setup.bat        # double-click, or: powershell -ExecutionPolicy Bypass -File .\setup.ps1
```

After setup, fill real keys into `backend\.env`, then launch with `start-app.bat` / `start-app.ps1`.

Frontend (root):

```bash
bun install
bun run dev               # vite dev server, canonical http://localhost:8080
bun run build             # production build
bun run lint
bun run format
```

Backend (`backend/`):

```bash
cd backend
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env       # fill in SUPABASE_URL / SUPABASE_SERVICE_ROLE_KEY / GEMINI_API_KEY
uvicorn main:app --reload --port 8000
```

API docs: http://localhost:8000/docs

Backend tests:

```bash
cd backend
pip install -r requirements-dev.txt
pytest
```

## Conventions

- **Routes**: TanStack Router file-based. New page = new `.tsx` in `src/routes/`. `routeTree.gen.ts` regenerates automatically on `bun run dev` / `build`.
- **Hooks**: React Query hooks live in `src/lib/hooks.ts`. Use the same query keys (`["viva-sessions"]`, `["presentations"]`) so `invalidateQueries` works everywhere.
- **API client**: `src/lib/api.ts` exports `api(path, init)`. Bearer token is read from `localStorage.cpn_token`. Default base URL: `VITE_API_URL` env or `http://localhost:8000`.
- **Backend modules**: each feature has its own router under `backend/api/`, schemas in `backend/models/`, AI logic in `backend/ai/`.
- **DB**: Supabase. Schema lives in `backend/supabase_schema.sql`. Apply via Supabase SQL editor.
- **Env**: secrets in `backend/.env`. Never commit. Frontend uses `VITE_*` envs.

## Endpoint surfaces

- `/api/auth/*` — login, signup, me
- `/api/projects/*`, `/api/teams/*` (atomic RPC create + self-heal list), `/api/files/*`
- `/api/tasks/*`, `PUT /api/projects/{id}/tasks/reorder` — Kanban board (4 statuses incl. Review, persisted `sort_order`)
- `/api/viva/*` — AI Mock Viva (sessions, start, answer, skip, hint, end, transcript, stats)
- `/api/presentation/*` — AI Presentation Mock (sessions, start, upload-slide, ask, end); `scenario_id` accepted on create
- `/api/catalog/scenarios`, `/api/catalog/personas` — the server-owned scenario/persona registry (`backend/ai/registry.py`); prompt text and rubrics stay server-side
- `WS /ws/live/{mode}/{session_id}` — real-time voice engine shared by Viva, Presentation, Pitch and Coach (`backend/api/live.py`); persists timestamped transcripts + evidence-backed observations to `session_events` and writes a structured `report` JSON on session completion
- `/api/college-predictor`, `/api/weakness-heatmap`
- `/api/advanced/*` — advanced features (bridge, etc.)
- `/api/privacy/*` — DPDP consent (log, status), data deletion (request, status), policy, grievance, parental verification (request, verify, status, withdraw)
- `/api/terms/policy` — Terms & Conditions (public, versioned, API-sourced)
- `/api/institution/*` — admin dashboard, students, readiness-report, weak-topics, invite, export (requires faculty/admin role)
- `/api/readiness/model` — PUT to switch DRS model (v1/v2); `/api/readiness/benchmarks` — peer percentile comparison

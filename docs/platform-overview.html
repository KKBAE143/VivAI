VivAI

An AI companion for engineering students who must build a project and defend it — viva, presentation, team review, and placement rounds — without treating those as separate apps.

VivAI is the student-facing product name of this platform. Students sign up, ground their work in a project workspace, practice oral defense with a live AI examiner, and get evidence-backed reports that tell them exactly what to fix next. The entire product is built around one idea: your project content should train the AI that trains you.

01 · Problem

Why VivAI exists

In Indian engineering colleges, evaluation is not “did you push code?” — it is can you stand in front of a panel and own the work? Final-year major projects, mini projects, PBL reviews, subject vivas, seminars, and placement project discussions all share the same failure mode: students prepare alone, late, with generic material that has never seen their repository.

What students actually face

  • Faculty open the report / code and grill design choices — practice tools ask textbook DSA.
  • First real pressure often is the exam itself; anxiety tanks delivery even when knowledge exists.
  • Group vivas expose free-riders too late; teams never practiced being cross-questioned together.
  • Presentation rehearsal is “read slides in the hostel”; nobody scores coverage gaps.
  • Students think in Hinglish / regional languages; most tools force formal English-only drills.
  • Tasks live in WhatsApp, docs in Drive, mock interviews on another site — no single readiness number.

What the market fails at

  • Generic interview bots — no project graph, no code context, no college viva format.
  • Project tools (Notion/Jira clones) — manage work, never train oral defense.
  • Slide-only coaches — ignore the viva that follows every seminar.
  • Faculty bandwidth — 1:1 mock vivas do not scale to an entire batch.

The gap is not “more AI chat.” The gap is a project-native oral practice system that closes the loop from build → present → defend → improve.

02 · Solution

What VivAI is

VivAI is a defense-readiness platform for college engineers. It combines a lightweight academic workspace with a high-quality live practice engine and longitudinal analytics — so every mock session is fed by real student work and feeds the next practice recommendation.

1 · Workspace

Projects (PBL / Mini / Major), Kanban, files, teams, templates, study bank — the academic source of truth the AI can read.

2 · Practice

Mock Viva, Presentation Mock, Pitch Drill, Communication Coach — text Q&A or full live voice with camera, scenarios, and personas.

3 · Insight

Evidence reports, delivery metrics, weakness heatmap, readiness score, college predictor, XP / streaks — so progress is measurable.

Positioning statement

VivAI is for B.Tech students who need to defend real project work under oral pressure. Unlike generic AI interview apps, VivAI uses the student’s project, code, and slides as context, runs realistic live examiners, and returns scores only when claims are backed by transcript evidence.

05 · End-to-end journey

How a student actually uses VivAI

This is the full lifecycle — from empty account to defense week — mapped to real screens and backend behavior.

  1. Account & identity

    Signup / login via email (Supabase Auth) or Google OAuth. Session token is stored client-side as cpn_token and sent as Authorization: Bearer … on every API call.

    Routes: /signup, /login, /forgot-password, /reset-password. API: /api/auth/*. Profile fields: full name, college, year, branch, roll number, goals.

  2. Onboarding (3 steps)

    Branch (CSE, IT, ECE, EEE, Mechanical, Civil, AI/ML, Data Science…), year, project type (PBL / Major / Mini / Research), and goals (“Ace my viva”, “Ship a demo”, “Land an internship”…). Completing onboarding seeds a first project best-effort and marks onboarding_complete.

    Route: /onboarding · API: POST /api/onboarding/complete

  3. Dashboard as home base

    Greeting by first name, Defense Readiness gauge, gamification strip (XP / level / streak), stats row, active projects, upcoming deadlines, quick prep CTAs, recent viva sessions, and teams. The dashboard is optimized for “what should I practice next?” not a vanity feed.

    Route: / · Data: readiness + dashboard analytics + projects + viva sessions + teams

  4. Build the project workspace

    Create PBL / Mini / Major projects with title, subject, tech stack, problem statement, description, deadline, semester. Upload files (PDF, PPTX, DOCX, images, ZIP). Drive a 4-column Kanban: To Do → In Progress → Review → Done with drag-and-drop order persisted as sparse sort_order integers.

    Routes: /projects, /projects/new, /projects/$id, /files. Reorder API: PUT /api/projects/{id}/tasks/reorder.

  5. Form a team

    Create team with atomic lead membership (Postgres RPC create_team_with_lead + compensating fallback). Invite via code, set Lead / Member roles, request project↔team linking, browse activity. Historical orphan teams self-heal on list.

    Routes: /teams, /teams/$id, project Team tab

  6. Prep materials (optional but powerful)

    Templates & checklists for project formats and viva structure. Study Bank turns material into question banks + spaced-repetition flashcards; any bank can convert into a focused viva session (to-viva).

    Routes: /templates, /study, /study/review

  7. Configure a practice session

    From Mock Viva setup: session type (Subject / Project / General), duration (5 / 10 / 20 / 30 min), difficulty (incl. Adaptive), persona from server catalog, language (13 options), subject chips or linked project. Presentation / Pitch / Coach flows pick scenario_id from the server-owned catalog (UI only sees safe public fields — rubrics and prompt text never leave the backend).

    Catalog: GET /api/catalog/scenarios, /personas. Create: POST /api/viva/sessions or presentation equivalent.

  8. Run the session

    Classic path: REST start → answer / skip / hint → end. Live path: WebSocket /ws/live/{mode}/{session_id} streams mic audio to Gemini Live and plays examiner speech back. Mic gate opens only after greeting playback finishes (prevents echo double-greeting). Model logs evidence-backed observations via tools; deterministic delivery metrics track fillers, WPM, talk ratio, latency.

    Modes on the shared live engine: viva, presentation, pitch, coach. Separate sockets exist for team viva and sentiment frame streams under /api/advanced.

  9. Receive a structured report

    On finalize, VivAI builds a versioned SessionReport: executive summary, weighted dimension scores, findings (strength / issue / note) with evidence refs, timeline, practice plan, recommendations, industry expectations, resources. Validator drops findings without valid evidence; body language is forced not_observed if camera was off; overall score is recomputed as rubric-weighted mean (not three identical vibes).

  10. Close the loops

    Weakness Heatmap updates across sessions. Presentation Bridge launches gap vivas. Readiness recomputes. XP awards (e.g. +50 viva, +50 presentation, +30 pitch). College Predictor improves as peers practice. Student returns to dashboard with a clearer next action.

06 · Workspace features

Where academic work lives

Workspace is not “Jira for students.” It exists so oral AI has something real to examine — and so teams stop coordinating exclusively in WhatsApp the week before review.

Projects

Source of truth

Students create and manage projects typed for Indian curricula: PBL, Mini, Major. Key fields — problem statement, subject, tech stack, description, progress %, status (In Progress / Under Review / Completed), deadline — are not decorative. Project-linked vivas pull this context into questioning.

  • Use case: Final-year CSE team documents “Smart Traffic using YOLO + MQTT” once; every viva reuses it.
  • Benefit: No re-explaining the project to the AI every session; continuity across weeks.
  • Routes: /projects, /projects/new, /projects/$id

Kanban board

Execution

Four statuses including a deliberate Review column (mirrors faculty checkpoint language). Drag-and-drop via @dnd-kit; order stored as sparse integers (×1000 gaps) with batch reorder API and optimistic TanStack Query updates so the board feels native.

  • Use case: Split “dataset cleaning / model training / report / slides” across teammates with due dates and priority.
  • Benefit: Defense prep becomes visible work, not last-night panic.

Teams & project linking

Collaboration

Teams are first-class: create, invite, join by code, change roles, remove members, activity feed. Project–team linking uses a request / accept flow so ownership stays clean when one student owns the project row but the team defends together. Create path cannot return a team the creator cannot see (atomic membership insert + list self-heal).

  • Use case: Four-member major project; Lead invites via code; Team Viva uses the same membership graph.
  • Benefit: Collaboration graph is real data, not a static “team name” field.

Files & templates

Artifacts

Uploads go to Supabase Storage (bucket configurable, default uploads) with metadata rows for listing/download. Templates hub serves structured guides + checklists (PBL, major, mini, viva) so students know expected academic shape before AI practice even starts.

07 · Practice engines

Signature oral practice

These are the product’s center of gravity. Everything else either supplies context to them or analyzes their outputs.

AI Mock Viva — signature feature

Simulates faculty oral examination. Three session types: Project (must link a project), Subject (topic chips like DBMS, OS, CN, ML…), General (broad technical). Students pick duration, difficulty (including Adaptive), persona, and language.

Two interaction modes

  • REST Q&A: start → answer → skip → hint → end; questions persisted in viva_questions.
  • Live voice: shared live engine; spoken examiner with interruption policies from persona.

Use cases

  • Night-before major project defense.
  • Subject viva prep mid-semester (DBMS normalization grilling).
  • Building speaking confidence for first-gen engineers.

Benefits

  • Unlimited safe failure before the real panel.
  • Hints without fully spoiling; adaptive depth when answers are strong/weak.
  • Transcript + delivery metrics + score history for deliberate practice.

Low-level

API prefix /api/viva. Live path WS /ws/live/viva/{session_id}. Rubric emphasis (viva defense): technical depth, clarity, responsiveness. Stats endpoint aggregates strengths/weaknesses across sessions.

AI Presentation Mock

Practice presenting project work to an AI panel. Supports slide image upload with Gemini VLM feedback, follow-up questions mid-presentation, and full live spoken delivery with scenario_id (project presentation, seminar, etc.).

Use cases

  • Seminar / review dry-run with actual deck screenshots.
  • Finding coverage holes (what you never said out loud).
  • Placement “explain your project” with slides.

Benefits

  • Multimodal: content of slides + spoken narrative.
  • Feeds Presentation → Viva Bridge automatically.
  • Delivery metrics for pace and monologue length.

Low-level

API /api/presentation/*. Rubric: structure, clarity, delivery. Pitch sessions can share presentation session storage with session_type: "Pitch".

90-Second Pitch Drill

Short-form persuasion practice examiners and recruiters open with: problem → solution → why now / why you. Timed drill with AI scoring; also available as a live pitch scenario (elevator pitch) under the shared engine.

  • Use case: First 90 seconds of any review or angel-style Q&A.
  • Rubric: problem framing, value proposition, delivery.
  • XP: +30 on completion (gamification table).
  • Route: /pitch-drill
Live session engine (shared infrastructure)

One WebSocket protocol powers Viva, Presentation, Pitch, and Communication Coach. That is intentional: latency-sensitive conversation stays thin; analytics stay fat and offline.

High-level flow

  1. Client creates session row via REST (authz + config).
  2. Opens WS /ws/live/{mode}/{session_id}.
  3. Server composes system instruction from mode + scenario block + persona block.
  4. Audio frames stream to Gemini Live; model audio returns for playback.
  5. Tools: log_observation (and legacy flag_moment) write evidence to session_events.
  6. On complete: delivery metrics + report generation + persistence.

Quality controls (non-negotiable product behavior)

  • Mic gate: open only after greeting audio drains (+ latency pad); barge-in opens immediately.
  • Server safety gate: drops early audio until first model turn_complete (20s release so it cannot deadlock).
  • Language TTS: BCP-47 speech_config.language_code for non-English; fallback strip if model rejects.
  • Observation dedupe: same (dimension, kind) within ~20s is not double-logged.
  • Evidence-log pattern: live model must not be the scorer; scoring is post-session only.

Scenario catalog (server-owned)

20+ scenarios across academic, placement, corporate, public — e.g. Project Viva Defense, Subject Viva, HR Interview, Technical Interview, Campus GD, Client Meeting, Daily Stand-up, Elevator Pitch, Panel Q&A. Each carries role, objectives, dialogue style, interaction policy, coaching focus, weighted rubric, opening move.

Personas (behavioral matrix, not adjectives)

ID Intent Pressure style
friendly Early practice Warm, generous hints, lenient scoring
calm Low-pressure precision Unhurried, measured feedback
balanced Default realistic examiner Fair follow-ups, standard difficulty
strict Defensible answers only Drills vague claims, scarce praise
hostile Tough panel simulation Skeptical, frequent probes — always formal register, never slang

Axes include tone, patience, interruption policy, follow-up depth, hint policy, encouragement, difficulty ramp, scoring stance, and vocabulary register (formal even when hostile).

Languages

Supported live-session labels (UI + DB CHECK aligned): English, Hindi, Hinglish, Telugu, Tenglish, Tamil, Tanglish, Kannada, Malayalam, Marathi, Bengali, Gujarati, Punjabi. Server normalizes unknown values to English so sessions never 500 on a bad language string.

08 · Advanced AI modes

Seven differentiators under /advanced

These modes extend the core loop in ways generic chat products cannot copy overnight. Each has dedicated routes under /advanced/* and APIs under /api/advanced/*.

A · Code-Aware Viva

Killer feature

Student uploads a project ZIP or links GitHub. VivAI extracts readable sources, stores a code_snapshots row, analyzes structure, then asks implementation-level questions (“why this concurrency model?”, “what breaks if this layer is removed?”). End report includes how much of the codebase the questioning covered.

  • Use case: Student who “used a tutorial stack” but must defend every choice.
  • Benefit: Simulates faculty who actually open the repo — the real exam behavior.
  • Route: /advanced/viva-code-aware

B · Presentation → Viva Bridge

Closed loop

After a presentation session, VivAI identifies weak topics (clarity / confidence / coverage gaps), generates targeted viva questions, and can launch a focused viva in one action. Presentation practice stops being a dead-end “nice dry-run.”

  • Use case: Seminar went okay but architecture explanation scored low → 8 gap questions overnight.
  • APIs: gaps, generate-questions, launch-viva, history.

C · Team Viva Mode

Realtime

Multi-member viva over WebSocket. Question broadcasts to the team; members race to answer; others can add corrections; scoring produces individual results plus a collaboration score. Mirrors how real group vivas put teammates on the spot.

  • Use case: Catch “only one member understands the backend” two weeks early.
  • Socket: /api/advanced/ws/team-viva/{session_id}/{profile_id}

D · Faculty Simulation

Personalization

Crowd-sourced professor profiles: subjects, style tags, tough topics, interruption habits, expected depth. Mock viva system prompt adopts that examiner’s pattern. Students can rate simulation accuracy after — improving the campus library over time.

  • Use case: “Prof. Sharma always starts with normalization and cuts vague answers.”
  • Benefit: Hyper-local prep no national interview app can offer.

E · Weakness Heatmap

Longitudinal

Aggregates scored viva answers across all sessions into topic-level weakness maps (per project and overall). Not a single-session grade — a running diagnosis: what you keep missing, how many times you practiced it, trend direction.

  • Use case: Three vivas in; indexing and thread-safety still red → prioritize those flashcards + gap viva.

F · College Viva Predictor

Network effect

Anonymized aggregation of what’s being asked across the college/batch for a subject — probability rankings, weekly trends, frequent recent questions, and personal risk (likely topics ∩ your weak topics). Improves only as more peers practice — a real moat.

G · AI Communication Coach

Multimodal

Live role-play across the scenario catalog (HR, GD, client meeting, public speaking…) with camera-aware coaching where required. Real-time delivery signals and an evidence report after. Surface: /advanced/sentiment-analysis (product label: Communication Coach).

09 · Insights & habits

Making practice stick

Defense Readiness score

Composite 0–100 the dashboard leads with. Weighted components (sum = 1.0):

  • Viva 35% — average completed viva scores
  • Presentation 20% — average presentation scores
  • Coverage 20% — topic mastery breadth across questions
  • Consistency 15% — sessions + active days in last 14 days
  • Project 10% — average project progress %

Also surfaces weakest topics so the score is actionable, not decorative. API: /api/readiness

Gamification

XP, levels (250 XP per level), daily streaks, badges.

  • Viva / presentation completed: +50 XP
  • Pitch completed: +30
  • Flashcards reviewed: +15
  • Question bank created: +20
  • Task completed: +10 · Project created: +15

Badges include First Viva, Getting Sharp (5), Viva Veteran (20), streaks 3/7, High Scorer (85%+), Presenter, Scholar (50 cards), Rising Star (level 5).

Study Bank

Question banks + spaced flashcards; due queue; convert bank → viva. Turns passive notes into oral reps. Route /study.

Progress & leaderboard

Unified progress view; analytics for dashboard stats, activity feed, trends; college/branch leaderboard for light social pressure. Routes /progress, /leaderboard.

10 · Scoring philosophy

Why VivAI reports are trustworthy

Students ignore feedback they cannot believe. VivAI separates conversation from judgment on purpose.

During the session

  • Model role-plays examiner / coach only.
  • Logs observations with evidence (quote or concrete detail).
  • Deterministic delivery metrics computed from timestamps — no LLM required.

After the session

  • One structured JSON report generation pass with hard citation rules.
  • _validate_report drops uncited findings.
  • Recomputes overall as weighted mean of rubric dimensions.
  • Camera off → body language section marked not observed.

What a SessionReport contains

version, framework id, scenario/persona, availability (audio/camera/screen), executive summary, scores (overall + dimensions with weights, explanations, evidence_refs), sections with findings (strength / issue / note + confidence), timeline, optional per-question breakdown, strengths, weaknesses, recommendations, practice_plan, industry_expectations, resources, metrics.

11 · Architecture

How the system is built

VivAI is a split full-stack system: a TanStack Start frontend talks to a Python FastAPI backend; Supabase holds data/auth/storage; Google Gemini provides language, vision, and live audio.

High-level

Browser (VivAI UI)
  TanStack Start · React 19 · Router · Query · Tailwind · Web Audio
           │ HTTPS + Bearer token              │ WebSocket audio/events
           ▼                                   ▼
FastAPI backend
  AuthZ · REST routers · Live WS · AI modules · report pipeline
           │                    │                    │
           ▼                    ▼                    ▼
   Supabase Postgres/Auth   Gemini API        Supabase Storage
   profiles, projects,        text / VLM /       code ZIPs, slides,
   sessions, events…          Live voice         documents

High-level explanation

The browser never holds Gemini keys or private rubrics. It renders routes, manages media devices, and calls APIs. FastAPI is the trust boundary: validates JWT, enforces project ownership and team membership, composes prompts, proxies Live audio, and writes reports. Supabase is system of record; Gemini is a pure capability provider.

Deploy split: frontend to Cloudflare Pages/Workers (Nitro cloudflare-module); backend on any long-running Python host (Fly, Railway, Render, VM).

Low-level design choices

  • Server-owned catalog in backend/ai/registry.py — scenarios/personas as dataclasses; public DTO strips prompts.
  • Thin live / fat analysis — observe on WS; score after finalize.
  • App-level authZ — service role Supabase client; no RLS dependency (ownership bugs are high severity).
  • Error middleware order — catch-all inside CORS so 500s remain readable to browsers.
  • Language normalization — never let a bad language string become a silent CORS failure.
  • Atomic team create — RPC + compensating transaction; list self-heal for legacy orphans.

Live path sequence (simplified)

  1. Authenticated REST creates session with mode, persona, scenario, language, project_id…
  2. Client loads preflight (mic/camera permissions, language, devices).
  3. WS connects; server builds instruction = base mode rules + scenario block + persona block.
  4. Model greets; client schedules audio; mic remains gated until playback drains.
  5. Turns continue; tool calls persist observations; transcript turns get timestamps.
  6. Client ends / model completes → delivery metrics from transcript → report_service → validate → store.
  7. UI renders Session Report; gamification + readiness consumers read updated rows.

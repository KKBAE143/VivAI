Four FastAPI `APIRouter` instances expose REST endpoints under `/api/projects`, `/api/teams`, `/api/advanced/team-viva`, and a flat `/api/projects/{id}/team/*` + `/api/teams/{id}/requests/*` namespace; they share two cross-cutting concerns via `core.deps`: `get_current_user` / `require_project_owner` for ownership checks and `user_from_token` for WebSocket auth. Database access goes through `core.database.get_supabase()` against Supabase tables (`projects`, `teams`, `team_members`, `project_team_requests`, `viva_sessions`).

- `backend/services/team_project_service.py` is the single writer of `projects.team_id`; both `teams.create_team` (instant link) and `project_team.link` / `accept_team_request` delegate to `activate_link`, which also auto-declines stale pending requests and emits activity-log entries.
- `api/project_team.py` imports `_is_unique_violation` and `_membership` from `api.teams` to reuse helper logic rather than duplicating it.
- `api/team_live.py` adds a WebSocket endpoint at `/ws/team-viva/{session_id}` that authenticates via a bearer token in query params, validates team membership, and delegates floor control, audio routing, and AI orchestration to `ai.team_room` and `ai.viva_core`.
- Legacy migration compatibility lives inside `api/teams.py`: `create_team` tries the `create_team_with_lead` Postgres RPC first and falls back to manual `teams`+`team_members` inserts when the function does not exist yet, rolling back on failure.
